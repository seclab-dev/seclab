# 操作日志与运行日志

## 模块边界

“操作日志”只管理可信状态变更与安全事件。Master 是唯一查询事实源，页面和 Docker 管理器均查询同一份追加只读记录。普通列表、详情、统计、心跳、预检和同步上报不产生操作日志。

“运行日志”只读取 Master 或 Agent 由 `tracing` 写出的受控轮转文件。运行日志不进入操作审计表，也不提供任意路径或原始文件下载。

## 操作事件

每个事件使用 UUIDv7 `eventId`，并分别保存模块、事件码、操作者、可信客户端 IP、来源节点、目标、结果、影响级别、追踪 ID 和可选任务 ID。详情只包含路由模板、允许的基础类型参数、稳定错误码和限长脱敏错误摘要。

文件后台任务把最多 500 个来源路径、可选目标路径、逐项状态、稳定错误码和脱敏错误摘要保存为结构化操作明细。单项和批量任务都只生成一个操作事件，任务 UUID 归入 `taskId`，具体路径不再借用通用目标或通知字段表达。操作事件清理时逐项明细同步级联删除，并沿用操作日志 180 天保留期。

目标同时保存稳定内部 ID 与写入时的领域名称快照。列表不展示目标，名称、类型和内部 ID 统一在详情中提供；后台操作、传输和拉取任务的 UUID 归入 `taskId`，不作为业务目标展示。列表使用分页连续序号，用户或来源名称后显示可信客户端 IP，时间固定为本地数字格式 `YYYY-MM-DD HH:mm:ss`。

Agent 在最终执行端先把事件写入 SQLite outbox，再按当前机器会话批量上报。Master 使用认证会话覆盖节点来源，并按 `eventId` 幂等写入。Master 协调的文件任务会在取得 Agent 终态后，将逐项结果与操作事件写入同一事务。确认送达的 outbox 项保留七天；Master 操作日志保留 180 天并由每日维护任务分批清理。

Master 自身产生的事件也必须先写入 SQLite durable outbox，再幂等汇入操作日志与通知投影。进程重启、数据库短暂失败或重复消费不得丢失或重复生成事件；已送达 outbox 项保留七天。

操作日志列表直接展示可信来源节点，并支持按 `origin_node_id` 筛选。Master 事件显示为主控，本地 Agent 显示为本地节点，远程 Agent 优先显示节点名称并保留节点 ID 作为回退；详情始终展示来源，不依赖业务参数是否包含 `nodeId`。

## 应用接入矩阵

Docker、节点、文件与编辑器、进程、磁盘、系统监控、终端、脚本、计划任务、套件生命周期、设置安全项和升级操作必须产生语义操作事件。防火墙、操作日志和运行日志当前为只读应用，不产生事件。通知已读与归档、桌面排序、主题、语言和编辑器偏好属于用户体验状态，明确不进入操作日志。

异步操作可以记录一次提交事件和一个最终事件；进度、下载、准备、心跳、预检与状态轮询只进入领域运行历史。升级计划的后台终态必须继承创建、启动或取消操作保存的可信用户、客户端 IP 与追踪 ID。

动态套件不得依赖代理请求方法推断审计语义。套件必须声明 `operation-logs.write` 能力，并使用实例令牌向 Agent 的 `/api/v1/agent/suite-runtime/operation-events` 提交 UUIDv7 幂等键、稳定事件码、双语名称、结果、影响级别和脱敏详情。用户通过套件代理发起变更请求时，Master 将可信用户上下文传给 Agent，Agent 签发与套件实例绑定且七天有效的 `operationContextId`；套件只能回传该 ID，Agent 据此恢复用户、客户端 IP 和 trace。缺少上下文的自主后台事件使用套件主体。套件不能自行声明平台用户身份。

## 运行日志游标

文件列表返回文件身份与版本。查询游标同时携带文件版本和字节位置；文件轮转、替换或截断后返回 `RUNTIME_LOG_CURSOR_STALE`。单次最多返回 300 行、扫描 8 MiB，扫描达到上限时通过 `scanTruncated` 明确表示结果不完整。

文件目录缺失、节点离线、服务停止、尚无日志文件、筛选无结果和请求失败是不同状态。运行日志内容在返回前再次执行敏感信息脱敏。
